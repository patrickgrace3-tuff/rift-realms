# Rift Realms

A browser MMO-style fan game: League of Legends champions questing in three original zones (Sunhollow Vale, Frostspine Peaks to the north, and the Thornveil Jungle) and a five-player dungeon (the Ashen Cathedral), with co-op for up to five players, parties and chat. Plain JavaScript, no build step. three.js and PeerJS load from CDNs; champion art and ability text load at runtime from Riot's Data Dragon.

## Run and test

- Play: open `index.html` in a browser, or `npm start` and visit the printed URL.
- After changing anything in `src/`, run `node scripts/stamp.mjs`. It writes `?v=<hash>` onto every script and stylesheet link in `index.html` and a build code into `<meta name="build">`, so browsers never run a mix of old and new files (that once froze the game, and once blacked it out). A small script in the page's head fetches the latest page and reloads once if its build code differs. A test fails if you forget to stamp.
- Errors show on screen through `reportError` (00-core.js), and each part of the main loop runs inside `guarded(...)`, so one failing part can't stop the world from drawing.
- Test: `npm test` (Node 20+, no dependencies). Run it after every change to game logic. Tests load the scripts in `index.html` order into one shared scope with a fake DOM, then play through every quest headless.

## Layout

Scripts are classic `<script>` files (not modules) loaded in order by `index.html`. They share one global scope, so a file can use anything declared in an earlier file. Top-level code may only call things from earlier files; inside functions, anything goes.

## How the game works

- **Players.** Each player has a side from `SIDES` (`blue` is always the host; guests get `red`, `green`, `violet`, `amber`). The host keeps one PeerJS connection per guest in `NET.guests`.
- **Host-authoritative.** Only the host runs `SIM.step`. Every player action is a command object passed to `SIM.input(W, side, cmd)` (the guest sends the same objects over PeerJS). Never change game state from UI code; add a command and handle it in `SIM.input`.
- **Validate every command** in `SIM.input`: guest input is untrusted. Look items up by id, check slot names against fixed lists, check distances to NPCs.
- **Snapshots.** `SIM.snapshot(W)` is the only thing clients render from. Keep it small: arrays for mobs, loot and shots. Gear is sent only when `c.gearVer` changes.
- **Units and zones.** The simulation uses world units: x 0 to 16000, y 0 to 24000 (y is north). Sunhollow Vale is y < 8000, Frostspine Peaks is 8000–16000 (`WH`), the Ashen Cathedral is x < 8000 above `DZ` (16000), and the Thornveil Jungle is x > 8000 above `DZ` (`inJungle`). The cathedral and the jungle are reached only by portal. Always pass x to `zoneAt(y, x)`. Each zone is an entry in `ZONES` (key, name, and its area as `x0, y0, w, h`); `zoneAt` finds the zone at a point. To add a zone: add it to `ZONES`, build its scene and set `ZONE_PICS[key]` to its map picture (a canvas); the minimap and the world map (right-click the map) then show it automatically. A ridge of `OBSTACLES` along y = 8000 blocks the way except at Greywind Pass (`PASS`). Clamp positions with `clampX` and `clampY`; each step `SIM.bound` keeps units inside their zone (the jungle's edges, the Vale and Peaks, or the cathedral's rooms). `ZONE_HINT` and `ZONE_HOME` hold each zone's arrival line and where you return to when you fall. `XF(x, y)` converts to three.js world space; `ZH(x, y)` is the ground height in either zone.
- **Effects.** The simulation reports events with `SIM.fx(W, { k: ..., side })`; `handleFx` in `08-ui.js` turns them into banners, numbers and visuals. Add `to: [sides]` to send an effect only to those players (party chat, invites, rolls); the host filters these per guest in `netBroadcast`.
- **Parties.** `W.parties`, `W.invites` and `W.rolls` live in the simulation; commands are `pinvite`, `paccept`, `pdecline`, `pkick`, `pleave`, `roll` and `chat`, handled by `SIM.socialInput`. A kill's XP, quest credit and quest drops go to `SIM.creditGroup` (the killer plus party members within `SHARE_RANGE`). Rare and better gear from a party kill goes to a Need/Greed/Pass roll instead of the bag.
- **Quests** are data in `QUESTS` plus `QUEST_ORDER`. Objective types: `kill`, `loot`, `deliver`, `explore`, `collect`, `interact`, `defend`. They're data-driven: `collect` names a node kind (`obj.node`; nodes come from `NODE_SPOTS`, text from `NODE_INFO`, art from `NODE_ART`); `interact` points are entries in `USE_POINTS` with their `quest`, `verb`, `idle` and `done` text (`use` commands index `USE_POINTS`); `defend` sets `place`, `mob`, `waves`, `from` (attack direction) and its `start`/`waveText`/`win` banners; `loot` items are drawn by `QUEST_ITEM_ART`. Scenes register quest visuals in `USE_FX` (lined up with `USE_POINTS`), `EXPLORE_FX` and `DEFEND_FX`. `prereq` can be one quest id or a list (`prereqMet`). `questFor(quests, npcId)` decides what an NPC offers. A new quest of an existing type needs only data; a new type needs a branch in `SIM.questTick` or `SIM.damage`, a line in `questLine`, and a case in `objectiveTarget`.
- **Experience.** `xpForLevel` sets the XP each level needs; it grows faster than linearly. Kill XP goes through `mobXp` (bonus for creatures above you, nothing for creatures 5+ levels below) and quest XP through `questXp` (less for quests 4+ levels below you, using each quest's `lvl`). Give every new quest and creature a level. The quest chain reaches about level 8 at the end of the Vale and 10 after the first Peaks quest.
- **Level gap in combat.** `levelGap(enemyLevel − heroLevel)` gives the miss chance, the share of damage heroes deal, and how much harder the enemy hits. It starts at a 2-level gap and gets worse each level (up to 75% misses, 25% damage dealt, double damage taken). `SIM.damage` applies it to every hero-versus-creature hit; a miss returns −1 and skips crowd control. Creature name plates colour the level: orange 2–3 above you, red 4+, grey when it gives no XP.
- **Abilities.** Each champion's Q/W/E/R is matched to one of 15 archetypes from its Data Dragon text (`buildKit`). Talents modify the base numbers through `applyTalents`, used by both the simulation and the HUD. Heal and shield abilities go to the living player nearest the cursor (within `ALLY_PICK` of it and `ALLY_RANGE` of the caster), otherwise to the caster (`SIM.supportTarget`).
- **Vendors and items.** An NPC with `shop: [itemKeys]` opens a shop instead of a quest dialog; `SHOP_ITEMS` holds prices and text. Commands: `buy` (checked against distance and coins) and `potion` (F; `POTION` sets the heal and cooldown). Only gear can be equipped: use `isGear(item)` rather than checking for a particular non-gear type. F drinks a potion; T talks to the nearest NPC.
- **Raid bosses** (`boss: true` in `MOBS`, e.g. Skarnvir in the Wyrm's Crown) skip the normal mob AI and run `SIM.bossTick`: threat (melee champions ×3, healing ×0.5), telegraphed attacks (a `warn` effect before they land), adds, a raid-wide storm, enrage, and a reset if everyone leaves. Heroes without a party of `RAID.party` nearby deal 10% damage. Bosses ignore crowd control. Kill credit and `raidLoot` go to every party member who fought. Rarity 4 is Legendary. The test `raid: a party of three…` plays a scripted tank/healer/damage party through the fight; use it to retune numbers in `RAID` and `MOBS.dragon`.
- **Audio.** Files live in `src/audio/` (`music/`, and `sfx/` for effects) so every build copies them. Use MP3. Music is per zone in `MUSIC` (keys match `ZONES`); it starts on "Enter world" (browsers need a click first), crossfades when the zone's track changes, and stops when you leave. Call sounds through `playSound(() => ...)` from render or UI code so a sound problem can never break the game. Add an effect by putting its file in `src/audio/sfx/`, adding `SFX.name = "src/audio/sfx/file.mp3"`, and calling `sfx("name")` where it should play (`handleFx` is usually the place). Only add audio you have the rights to, and credit it in the README.
- **Who can hit whom.** Always ask `SIM.hostile(attacker, target)` (or use `SIM.enemies(W, attacker)`), never compare `team`. Heroes and creatures are always hostile; two heroes only while they're in a running duel together. Heals and shields never go to a hostile player.
- **Duels.** Right-click a party member's portrait → Challenge to a duel. Commands: `duel`, `duelaccept`, `dueldecline`, `duelyield`. Accepting drops a flag halfway between the two (`W.duels`, snapshot `du`), counts down 5 → Fight!, then `SIM.duelHit` stops the loser at 1 health and ends the duel (nobody dies). Leaving `DUEL.radius` for `DUEL.outGrace` seconds forfeits; death or a disconnect cancels.
- **Arena.** Arenamaster Vex (`arena: true` NPC) runs the Champion's Ring (`ARENA`). The `arena` command queues `W.arenaReqs`; the host's `serviceArena` (07-world.js) picks a random champion from `champs` and calls `SIM.arenaStart`, which spawns a computer hero (`bot: true`, side `bot<n>`, not in `SIDES` so it can't be commanded) at your level and gear and starts an arena duel. `SIM.botTick` drives it: dodges skillshots and blasts, leads its aim, kites or gap-closes, shields/heals/drinks potions. The player picks a difficulty 1–10 in Vex's window (`arena` command's `diff`); `arenaSkill(diff)` sets reaction time, dodge chance, aim, ability use, damage (`skill.dmg`, applied in `SIM.damage`), health (`hpMult`), gear rarity, potions and kiting. Tests: difficulty 1 should lose to an average player and 10 should beat one. Wins pay `ARENA_RULES.reward` × difficulty × level and track `arenaWins` and `arenaBest`; the opponent leaves 2.5 s after the duel. Hide `bot` heroes from player lists.
- **Hired raid party.** While the Skarnvir quest is active, Scout Yrsa (`mercs: ["rimewyrm"]`) offers "Hire a raid party". The `hire` command (party leader only, near Yrsa, `MERCS.price` × level coins per champion) uses `mercPlan` to fill the party to `PARTY_MAX` with one tank, one healer and damage, based on each member's `heroRole` (heal ability, or Support with a shield → healer; Tank tag → tank; else damage). It queues `W.mercReqs`; the host's `serviceMercs` (07-world.js) picks fitting champions by tag and calls `SIM.mercDone`, which spawns them (`bot: true`, `merc: { owner, role }`, side `merc<n>`, Rare gear at your level) into your party and refunds any it couldn't fill. `SIM.mercTick` plays each role: the tank holds threat (`tankThreat`, `tankArmor`, `tankHp`), the healer has its own steady heal plus its kit heals and shields, damage kills whelps then hits the boss from the side; all dodge telegraphs and follow you. They take no loot or rolls. Sister Elowen in the cathedral hires out a party the same way (an NPC's `mercs` lists the quests that allow it). They stay through the Ashen Cathedral and leave `MERCS.leaveAfter` seconds after its last boss dies (`SIM.mercsDismiss`), or as soon as they're kicked or you leave the party.
- **The Ashen Cathedral** (dungeon, `CATHEDRAL` in 01-world-data.js, logic in 05g-dungeon.js). Killing Skarnvir sets `W.riftOpen` and opens the **Rift** (`RIFT`) in the Wyrm's Crown; anyone whose `rimewyrm` quest is ready or done can always use it. Stepping in takes your whole party within `DUNGEON.carry` (hired champions too) to the narthex; the exit portal (`CATHEDRAL.exit`) leads to Yrsa's Watch. Walkable space is the rooms in `CATHEDRAL_ROOMS` (rectangles that overlap by 400 so big units pass between them); `SIM.bound` keeps units inside, and walls are drawn wherever a room edge doesn't open into another room. Pillars are `OBSTACLES`. Creatures come from `CATHEDRAL_SPAWNS` (each with its own home; a `pack` pulls together) rather than `MOBS.count`. Ashen Acolytes shoot firebolts (`ranged`, `W.mshots`) and heal allies (`heals`); Cinderfist Monks are melee. Bosses have `script` in `MOBS` and run `SIM.dbossTick` with the abilities and phases in `DBOSS`: Deacon Varrow (west chapel), Abbess Ysolde (east chapel; her palm silences: `silenceT` blocks casting), and Archprelate Malchar, the Ashen Saint (choir). The choir is sealed (`W.dungeon.sealed`) and the Saint immune until both chapel bosses die. Telegraphs are `SIM.danger(W, boss, { shape: circle | cone | line | donut | pulse, ... })`: a `warn` effect, then they land on whoever `SIM.inDanger`; `hazard` leaves burning ground (`W.hazards`). Computer heroes use `SIM.dangerEscape` to get out. `SIM.dungeonLoot`: every player who fought gets an Epic; the Saint also drops one Legendary (rolled on) and sends hired champions home. Sister Elowen gives the three quests and also hires out a party. Everything respawns `CATHEDRAL.resetAfter` seconds after the last player leaves. The test `cathedral: a player and a hired party clear it…` plays the whole dungeon; use it to retune numbers.
- **The Thornveil Jungle** (levels 15–18; data in 01-world-data.js under `J(x, y)`, jungle-local positions). When the Saint dies (`W.dungeon.down.saint`, snapshot `dg.sd`) two portals open behind his altar (`CHOIR_PORTALS`): the right one takes your party to Canopy Camp (`JUNGLE_ARRIVE`); the left one is sealed for a future area. The camp's waystone and its twin by Highwatch Outpost (`WAYSTONES`) link the jungle with the Peaks for anyone who has killed the Saint or started a jungle quest (`SIM.canEnterJungle`). Ranger Tamsin and Herbalist Ezo give nine quests (`frogs` … `queen`); Quartermaster Bao sells potions; Tamsin hires out raid parties. Creatures: Jade Leapers, Vine Serpents, Striped Prowlers and Howler Apes (packs), Delta Crocodiles; elites Greyback (charges) and Sizzra (spits from range, drops the venom sac). Raid bosses use the cathedral's boss engine (`script`, `DBOSS`, `SIM.danger`) and `LOOT.dungeon: "raid"` (an Epic each plus a rolled Legendary): Mawgrot dives twice (`hidden` + `immune`, mob snapshot flag 16; he ambushes from below, his crocodiles join, then `SIM.surface` telegraphs where he erupts), and Shadowmane vanishes twice (shadow strikes, her cubs, then she pounces on the weakest). The test `jungle: a level 17 player can do every quest before the raids alone` should end around level 19; `jungle: Mawgrot dives…` plays both raids with a hired party.
- **Saved progress.** Each champion's progress is kept in the player's own browser under `rr.save.<champion id>` (08d-save.js), built from their hero in the snapshot by `saveRecord`: level, XP, coins, quests, bags, equipped gear, talents, arena record and position. It saves every few seconds, when leaving the world and when the page closes. Picking a champion with a save shows "Continue" (and "Start over") on the select screen. The host applies a save once, when the hero joins: its own in `startWorld`, a guest's from the `hello` message. `SIM.loadSave` treats every save as untrusted: known quests and states only, items rebuilt from known fields with fresh ids and clamped stats, talents replayed through `canTalent`, a position inside the cathedral moves to its entrance, and a position in the jungle is kept. Timed quests and defenses restart. Bump `SAVE_VERSION` if the format changes (old saves are then ignored). Anything new a hero keeps between sessions belongs in `saveRecord`, `SIM.loadSave` and the snapshot, with a test.
- **Obstacles** are circles in `OBSTACLES`. Moving units slide around them; avoid placing two circles so they touch and form a corner (merge them into one, like Osric's stall). A test fails if any two obstacles leave a gap narrower than a player.

## Rules for this project

- It is a free fan project under Riot's "Legal Jibber Jabber" policy. Keep it free: no ads, payments or sponsorships. Keep the disclaimer on the select screen. Never commit Riot assets (images, models, game files) to the repo; load them from Data Dragon at runtime.
- Characters, NPCs, creatures, the zone and all quest text are original. Keep new content original too; don't recreate Riot's maps or other games' characters.
- Art: pixel bodies drawn on 128x192 canvases in 4px blocks, with the champion portrait as the head. Creatures are drawn in code in the same style.
- Keep it dependency-free unless there's a strong reason. If adding a library, pin an exact version.
